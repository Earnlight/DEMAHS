# Immersive reader pilot

The paginated illuminated-manuscript reader is enabled only on `advice.html`, the existing reader with the most chapter text (10 paragraphs, 4,114 characters). Every other chapter keeps its existing reader presentation. The library and the reader’s chapter drawer display the existing topic-led covers as illustrated shelves; all original chapter links and collection order remain intact. The catalogue contains metadata for the existing 33 chapters so navigation and collection search retain the original library order and routes.

The implementation uses the existing static GitHub Pages deployment, artwork and local fonts. Original chapter nodes move into the new interface; chapter text is not duplicated into a runtime dataset. All 38 HTML documents, their original scripts, content, links and metadata remain identical to revision `4042953` after stripping the three added asset hooks on Advice.

Shared assets are `assets/scripts/immersive-reader-bootstrap.js`, `assets/scripts/immersive-reader.js`, `assets/styles/immersive-reader.css` and `assets/reader-catalog.json`. The library enhancement lives in `assets/styles/library-shelf.css` and `assets/scripts/library-shelf.js`. The bootstrap protects existing reading records before legacy scripts initialise. New notes, highlights, bookmarks, appearance and position records use `demahs.reader.*.v1` local storage keys; legacy bookmarks and highlights are imported without deleting their original records. The reader exposes `window.DemahsReader` and reading-position events for a future narration integration, without generating audio or simulated timings.

CSS columns divide the original selectable text into viewport-sized pages without duplicating or rewriting content. Previous/next page controls, arrow/Page Up/Page Down/Home/End keys, touch swipes and Go to page navigate real rendered pages. Page counts are measured from rendered fragments, including paragraphs split across columns. Layout updates include a bounded timer fallback for browsers that throttle animation frames while a modal settings panel is open. Character anchors retain the passage through appearance changes, rotation and fullscreen. Notes, highlights and imported legacy bookmarks keep their original block anchors.

Fullscreen removes the reader header and sidebar, fills the visual viewport, preserves essential bottom controls and supports native standard/WebKit APIs with navigation UI hidden where supported. Installed PWAs use their existing app window. Safari browser tabs that lack native fullscreen still get an expanded reading surface; iPhone browser bars require launching from the Home Screen.

Run `python3 scripts/verify-reader-pilot.py` against a static server, setting `DEMAHS_TEST_URL` if necessary. `DEMAHS_TEST_BROWSER=webkit` selects Safari’s rendering engine. Checks cover original content preservation, every chapter-text glyph fitting within its rendered page, real page counts/navigation, phone landscape/portrait layouts, fullscreen entry/exit, PWA fallback and rotation, large text/spacing reflow, bookmarks/resume, persistent annotations, search results, cover filtering, library order and overflow. Earlier pilot checks also covered the dictionary and external comment form using intercepted responses. No test submits a real comment. Physical Home Screen testing remains outstanding.

The supplied illuminated-manuscript reference guides the parchment, dark-and-gold frame, celestial panorama, illustrated navigation and page controls, using existing artwork. Discussion and associated original links remain available through About & discussion, retaining their original destinations. The service worker uses a new cache version and includes the new assets so installed readers can update.

Publishing this pilot is explicitly authorised. Extending the design to other chapters awaits the user's assessment of Advice.
